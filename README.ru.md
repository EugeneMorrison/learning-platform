## Что делает платформа

Авторы собирают курсы из блоков: теория, тесты и задачи на код. Студенты проходят уроки блок за блоком. Готовый урок можно вставить на любую страницу через `<iframe>`.

Автор может:

* Создавать и редактировать курсы, уроки и блоки, собирая блоки прямо в браузере (HTML-файл не нужен)
* Импортировать уроки из HTML-файлов, когда нужно загрузить сразу много материала
* Давать студентам доступ, записывая их на курс
* Видеть прогресс каждого студента и общую статистику
* Возвращаться к любой отправке студента, включая неверные, со временем до секунды и тем самым кодом, который он запускал
* Общаться с каждым студентом в живом чате

Студент может:

* Читать теорию с подсветкой синтаксиса в примерах кода
* Отвечать на тесты, сразу видеть результат и пробовать снова после ошибки
* Писать и запускать Python в редакторе в стиле PyCharm (CodeMirror 6 с темой Darcula: подсветка ключевых слов, парные скобки, подсветка встроенных функций)
* Следить за собственным прогрессом по курсу
* Переписываться с преподавателем в реальном времени

## Система блоков

Урок — это список блоков. Типов четыре:

| Тип  | Описание                      | Формат хранения                                                                        |
|------|-------------------------------|----------------------------------------------------------------------------------------|
| TEXT | Теория с HTML-форматированием | `{"html": "<p>...</p>"}`                                                               |
| QUIZ | Тест с выбором ответа         | `{"question": "...", "options": [...], "correct_answer": 0, "explanation": "..."}`     |
| CODE | Задача на Python              | `{"prompt": "...", "starter_code": "...", "tests": [...]}`                             |
| FILL | Задача «заполни пропуски»     | `{"prompt": "...", "template": "print({{8}})", "case_sensitive": false}`              |

CODE-блоки работают на CodeMirror 6 с самописной темой PyCharm Darcula ([frontend/src/components/pycharmDarcula.js](frontend/src/components/pycharmDarcula.js)):

* Оранжевые ключевые слова (`if`, `def`, `and`, `True`)
* Зелёные строки, синие числа, фиолетовые встроенные функции (`print`, `input`, `len`, `range` и ещё около 60), которые выбирает ViewPlugin, обходящий синтаксическое дерево
* Шрифт JetBrains Mono, тёмный фон `#2B2B2B`
* Подсветка парных скобок, авто-отступ, Tab для отступа
* Собственная нумерация строк CodeMirror и подсветка активной строки в нумерации

## Визуальный редактор блоков

Автор собирает урок блок за блоком прямо в браузере. Без HTML-файла и без команды `import_lesson`. HTML-импортер остаётся для массовой загрузки, но повседневная работа идёт в интерфейсе.

Чтобы открыть редактор, зайдите на страницу курса: у каждого урока есть кнопка «Редактировать» (только для автора), которая открывает редактор по адресу `/lesson/<lesson-uuid>/edit/`. Кнопка «Предпросмотр» рядом переключает на обычный вид студента.

В редакторе можно:

* Добавить блок любого типа — Теория (TEXT), Тест (QUIZ), Задача на код (CODE), Заполнить пропуски (FILL)
* Изменить любой существующий блок на месте
* Удалить блок, с подтверждением
* Двигать блоки вверх и вниз

У каждого типа блока своя форма:

| Тип  | Интерфейс редактирования |
|------|--------------------------|
| TEXT | WYSIWYG-редактор (TipTap): жирный, курсив, H2/H3, маркированные и нумерованные списки, строчный код, блок кода, цитата. Преподаватель не пишет HTML руками; редактор сам формирует `{"html": ...}`, который и сохраняется. Блоки кода превращаются в `<pre><code>` и автоматически подсвечиваются при просмотре урока. Есть загрузка изображений (кнопка, вставка из буфера, drag-and-drop) и отмена/повтор. |
| QUIZ | Вопрос в том же редакторе, динамический список вариантов, переключатель для правильного варианта и пояснение при верном ответе. Пустые варианты убираются при сохранении, а `correct_answer` переиндексируется автоматически. |
| CODE | Условие в WYSIWYG, `starter_code` и необязательное скрытое решение (оба — в том же редакторе CodeMirror + PyCharm Darcula, что и у студента), плюс таблица тестов (stdin → ожидаемый stdout). Пустые строки тестов игнорируются. |
| FILL | Условие в WYSIWYG плюс шаблон, где пропуски пишутся прямо в тексте как `{{ответ}}` (варианты через `\|`, например `print({{math.factorial(8)\|factorial(8)}})`). Живой предпросмотр показывает фиксированный текст и принимаемые ответы. Учёт регистра и пояснение — по желанию. |

Пара деталей реализации:

* Файлы: [frontend/src/pages/LessonEditor.jsx](frontend/src/pages/LessonEditor.jsx), [frontend/src/components/RichTextEditor.jsx](frontend/src/components/RichTextEditor.jsx) (+ `.css`), [frontend/src/components/FillBlock.jsx](frontend/src/components/FillBlock.jsx), [frontend/src/lib/fillTemplate.js](frontend/src/lib/fillTemplate.js), [frontend/src/lib/pythonHighlight.js](frontend/src/lib/pythonHighlight.js).
* Редактор работает через существующий DRF `BlockViewSet` (`POST` / `PUT` / `PATCH` / `DELETE /api/blocks/`). `BlockSerializer` проверяет обязательные поля для каждого типа блока и возвращает `400` при некорректном содержимом. Доступ только у автора через права `IsAuthor` / `IsOwnerOrReadOnly`.
* Загрузка изображений: `POST /api/upload-image/` (только автор) сохраняет файл в `MEDIA_ROOT/lesson_images/` и возвращает абсолютный URL, который редактор вставляет как `<img>`. Раздаётся из `/media/`, хранится в Docker-томе.
* Проверка FILL идёт на сервере в `ProgressSubmitView` (`grade_fill()` обрезает пробелы, по желанию не учитывает регистр и требует совпадения по всем пропускам). Вьюер дополнительно проверяет на клиенте для мгновенной обратной связи. Поля-пропуски растут по мере ввода.
* Порядок и уникальность: у `Block` есть ограничение `unique_together (lesson, order_index)`. Новые блоки получают `max(order_index) + 1`, а не «количество + 1», поэтому пропуски после удалений не вызывают конфликтов. Перестановка меняет два блока местами через временный свободный индекс, чтобы не нарушить ограничение в процессе. Создание урока на странице курса использует то же правило `max + 1`.

## Чат в реальном времени (WebSocket)

Чат преподавателя со студентом работает через Django Channels, так что сообщения появляются сразу — без поллинга и без перезагрузки.

* Бэкенд: ASGI-сервер (Daphne) + Channels 4. WebSocket-эндпоинт: `ws/chat/<course_id>/<other_user_id>/?token=<jwt>`.
* Авторизация: браузер не может добавить заголовок Authorization в WebSocket-handshake, поэтому JWT access-токен передаётся в query-string. Небольшой middleware ([api/ws_auth.py](api/ws_auth.py)) проверяет его и кладёт `User` в scope соединения.
* Комнаты: имя группы строится из отсортированной пары `(user_id_A, user_id_B)` внутри курса, поэтому обе стороны попадают в одну комнату независимо от того, кто подключился первым. Посторонние и пары «студент↔студент» отклоняются с кодом закрытия WebSocket 4003.
* Channel layer: `InMemoryChannelLayer` в разработке, так что ничего дополнительно поднимать не нужно. Для продакшена — `channels_redis` + Redis.
* Хранение: история сообщений по-прежнему отдаётся обычным HTTP-эндпоинтом и загружается один раз при открытии чата. WebSocket несёт только новые сообщения.

## История попыток

Каждая отправка ответа на QUIZ или CODE пишется в таблицу `Attempt`. Это отдельно от `Progress`, которая хранит только последний ответ и счётчик.

* На странице прогресса студента кликните по «пилюле» `попыток: N` рядом с задачей, чтобы развернуть полную историю отправок.
* В каждой записи — время до секунды (`ДД.ММ.ГГГГ ЧЧ:ММ:СС`) и отметка «верно/неверно».
* Клик по конкретной попытке показывает, что именно отправили: для CODE-блока — код с той же темой CodeMirror PyCharm Darcula, что и в редакторе; для QUIZ-блока — номер выбранного варианта.

## Аутентификация и роли

JWT-аутентификация с двумя ролями:

* AUTHOR — создаёт, редактирует и удаляет свои курсы, уроки и блоки
* STUDENT — смотрит опубликованные курсы, записывается, отправляет ответы

Access-токены живут 7 дней, refresh-токены — 30. Axios-interceptor в [frontend/src/api.js](frontend/src/api.js) обновляет access-токен по 401 и повторяет исходный запрос. Сессия очищается, только если сам refresh-запрос провалился.

## Встраивание через iframe

Django отдаёт каждый урок по адресу `/lesson/<uuid>/`. React считывает UUID из URL и загружает урок через API. На маршруте стоит декоратор `@xframe_options_exempt`, поэтому его можно встроить в iframe на другом сайте.

```html
<iframe
  src="http://your-server/lesson/<lesson-uuid>/"
  width="100%"
  height="700px"
  frameborder="0">
</iframe>
```

В корне репозитория есть `iframe_test.html`, чтобы проверить это локально.

## Как запустить

Понадобится [Docker Desktop](https://www.docker.com/products/docker-desktop/).

1. Клонировать и запустить:

```bash
git clone https://github.com/EugeneMorrison/learning-platform.git
cd learning-platform
docker-compose up --build
```

Дальше Docker делает всё сам:
- Ставит зависимости Python и Node (Channels и Daphne включены)
- Собирает React-фронтенд
- Выполняет миграции базы
- Загружает тестовые данные (пользователи, курсы, уроки, блоки)
- Запускает ASGI-сервер на порту 8000

2. Открыть урок в браузере:

```
http://localhost:8000/lesson/6f1c0c31-7be5-4434-ac25-c00f8031d15c/
```

3. Проверить встраивание через iframe:

Откройте `iframe_test.html` из корня проекта (двойной клик в Проводнике). Он загружает тот же урок внутри `<iframe>` — именно так платформа встраивается на других сайтах.

Остановить: `Ctrl+C` в терминале, затем `docker-compose down`.

Следующие запуски, без изменений в коде: `docker-compose up` — без `--build`, используется кешированный образ.

## Ручная установка (без Docker)

Через Docker проще, но всё можно поднять и руками. Понадобятся:

* Python 3.12+ — [python.org](https://www.python.org/downloads/)
* Node.js 20+ — [nodejs.org](https://nodejs.org/), нужен для сборки React-фронтенда

> Важно: папка `frontend/dist/` в `.gitignore`, потому что это артефакт сборки. После свежего клонирования её ещё нет, и Django не сможет отдавать фронтенд, пока вы его не соберёте. Если выполнить только шаги Django, получите предупреждение `staticfiles.W004` и пустую страницу урока. Docker собирает фронтенд за вас, ручной путь — нет.

1. Бэкенд — зависимости Python:

```bash
python -m venv venv
venv\Scripts\activate           # Windows (PowerShell/CMD)
# source venv/bin/activate      # macOS / Linux
pip install -r requirements.txt
```

2. Фронтенд — собрать React-приложение (этот шаг часто забывают):

```bash
cd frontend
npm install
npm run build
cd ..
```

Команда создаёт `frontend/dist/`, которую Django использует и как директорию шаблонов (для `index.html`), и как директорию статических файлов (для JS/CSS-бандлов).

3. Django — миграции, фикстуры, сервер:

```bash
python manage.py migrate
python manage.py loaddata fixtures.json
python manage.py runserver
```

> В логе запуска должно появиться «Starting ASGI/Daphne version 4.x development server» — так понятно, что WebSocket подключены. Если вместо этого пишет «Starting development server» (WSGI), проверьте, что `daphne` стоит первым в `INSTALLED_APPS`.

4. Открыть в браузере — Django работает на порту 8000:

```
http://localhost:8000/lesson/6f1c0c31-7be5-4434-ac25-c00f8031d15c/
http://localhost:8000/login/
http://localhost:8000/admin/
```

> Не открывайте `http://127.0.0.1:5173/`. Это порт dev-сервера Vite, и он работает только если вы отдельно запустили `npm run dev` внутри `frontend/`. При обычной ручной установке всё отдаёт Django на порту 8000.

Повторный запуск после изменений:

* Бэкенд (Python) — просто перезапустите `python manage.py runserver`.
* Фронтенд (React) — заново выполните `npm run build` в `frontend/` и обновите страницу. Либо запустите `npm run dev` на порту 5173 для горячей перезагрузки во время активной работы — но запросы API и WebSocket всё равно идут в Django на 8000.

## Какой порт использовать? (8000 vs 5173)

Вот на чём обычно спотыкаются. Серверов два, у каждого своя задача:

| Порт | Сервер | Что делает | Когда работает |
|------|--------|------------|----------------|
| 8000 | Django | Бэкенд: REST API, база, WebSocket-чат, медиа. Ещё раздаёт собранный фронтенд. | Всегда (ваш `runserver` / PyCharm). |
| 5173 | Vite | Dev-сервер фронтенда (UI React) с мгновенной горячей перезагрузкой. За данными ходит в Django на 8000. | Только пока запущен `npm run dev`. |

Запустить можно двумя способами:

A) Режим разработки (удобно при написании кода) — два терминала, открывать `:5173`

Терминал 1, бэкенд:
```bash
python manage.py runserver        # → http://localhost:8000  (в логе должно быть "Starting ASGI/Daphne")
```
Терминал 2, фронтенд:
```bash
cd frontend
npm run dev                       # → http://localhost:5173
```
Затем откройте `http://localhost:5173/`. Правка React-файла сразу обновляет страницу. Запросы API и чата всё равно идут в Django на 8000 в фоне.

B) Как в продакшене — один сервер, открывать `:8000`

Соберите фронтенд один раз, и Django раздаёт всё сам:
```bash
cd frontend && npm run build && cd ..
python manage.py runserver        # → откройте http://localhost:8000/
```
Горячей перезагрузки тут нет — после каждого изменения фронтенда нужно заново `npm run build`.

Если что-то выглядит сломанным:

* `localhost:5173` не открывается, а `8000` работает → Vite не запущен. Запустите `npm run dev`.
* `5173` открывает страницы, но вход / данные / чат не работают → Django не запущен или не на 8000.
* Не работает именно чат → убедитесь, что запущен ровно один `runserver` и в его логе написано «Starting ASGI/Daphne». Убейте лишние `runserver`, занявшие порт 8000 (на Windows: `Get-CimInstance Win32_Process -Filter "Name='python.exe'" | Where-Object { $_.CommandLine -like '*runserver*' } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }`).

## API-эндпоинты

### Авторизация


### WebSocket — чат в реальном времени

```
ws://host/ws/chat/{course_id}/{other_user_id}/?token={jwt_access_token}
```

Отправка сообщения: клиент → сервер JSON `{"text": "..."}`.
Получение сообщений: сервер → клиент сериализованный `Message` JSON, рассылается обоим участникам сразу после сохранения.

## Маршруты фронтенда

```
/login/                                    Форма входа
/register/                                 Регистрация с выбором роли (Студент/Автор)
/dashboard/                                Дашборд по роли пользователя
/courses/:courseId/                        Страница курса (автор/студент)
/courses/:courseId/students/:studentId/    Автор: прогресс студента с историей попыток
/lesson/:lessonId/                         Просмотр урока
/lesson/:lessonId/edit/                     Автор: визуальный редактор блоков
```

* Дашборд автора: список своих курсов (через `/api/courses/my_courses/`) и форма создания курса.
* Дашборд студента: список курсов, на которые записан, с датами записи.
* Страница курса (автор): список уроков (у каждого кнопки «Редактировать» и «Удалить»), форма добавления урока и список студентов с кнопками «Прогресс» и «Чат». Чат открывает WebSocket-соединение, привязанное к конкретному студенту.
* Редактор урока (автор): добавление, изменение, удаление и перестановка блоков TEXT, QUIZ и CODE с формами по типам и WYSIWYG-редактором для теории. «Предпросмотр» открывает вид студента.
* Страница прогресса студента: % завершения, выполненные задачи, правильные тесты и разбивка по урокам. У каждой задачи есть «пилюля» `попыток: N`; клик по ней раскрывает полную историю отправок со временем, а клик по попытке показывает отправленный код или ответ с подсветкой синтаксиса.
* Просмотр урока: редактор CodeMirror в стиле PyCharm для CODE-блоков и всплывающий чат, подключённый к преподавателю по WebSocket.
